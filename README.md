# DevOps Project – Git 

## Objective
Manage a DevOps project using Git and GitHub best practices.

## Tools
- Git
- GitHub

## Branching Strategy
- main → production-ready code
- dev → development branch
- feature/* → new features

## Workflow
1. Create feature branch
2. Commit changes
3. Raise Pull Request
4. Merge into dev
5. Merge dev into main

📂 Repository Structure
devops-git-project/
│
├── README.md
├── .gitignore
├── TASKS.md
└── (project files)   

📝 Files Description

 README.md → Project documentation

.gitignore → Ignored files and directories

🧾 .gitignore Usage

The .gitignore file is used to prevent unnecessary or sensitive files from being tracked by Git, such as:

● Log files

● Environment files

● Build artifacts

🔁 Pull Request Strategy

● Feature branches are merged into dev using Pull Requests

● dev branch is merged into main after review

● Direct commits to main are avoided

✅ Deliverables

● GitHub repository with proper commit history

● Branching strategy implementation

● Pull requests and reviews

● README documentation

● .gitignore file

● Git tags

● Markdown-based task documentation
